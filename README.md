# 谷神页面离线编辑器 0.2.0

默认加载从谷神平台下载的原版设计器，离线编辑本地 `PG-*.json` 的已有字段属性和前端事件。保存 JSON 后，继续使用现有 SVN 工具提交，由平台自动同步。

## 安装与使用

1. VS Code 扩展面板菜单 → **从 VSIX 安装** → 选择 `gushen-page-editor-0.2.0.vsix`，按提示重载窗口。
2. 打开谷神导出源码工作区，打开一个 `PG-*.json`。
3. 标签页右键 → **重新打开方式** → **谷神页面编辑器**。
4. 在原版界面中修改字段设置或前端事件，先点对话框的“确定”。确认后的修改自动同步到当前文档。
5. 点击顶部 **保存 JSON**，或按 Ctrl / ⌘ + S。检查 SVN 差异后按现有流程提交。

设置对话框尚未确认的输入不会保存。外部文本修改与设计器编辑冲突时，保留当前设计器输入并停止写入；先复制需要保留的内容，再点击“放弃设计器修改并重载”。

本插件不执行 SVN 提交，不连接平台账户，不查询业务数据库，不执行事件脚本。

## 独立静态资源目录

```text
platform-assets/       原版资源快照，可整体替换
  snapshot.json        文件来源、路径、SHA-256 和大小
  guthon/              原始 HTML、JS、CSS、字体、图片、Monaco workers
native-designer/       独立离线适配代码和工具条
src/                   VS Code 文档与原文精确修改
designer-assets/      旧版简化字段/事件编辑界面
```

原版资源不做落盘改写。加载时由适配器重定向资源路径，并在应用创建前接入本地数据与文档消息。CSP 禁止连接网络；编辑器工作线程只加载本地资源。上游业务写接口均不执行。

快照共 **109 个文件，14,842,213 字节**。初始网页的 107 个静态依赖之外，实际界面测试补齐了 `editor.worker.js` 和 `ts.worker.js`。

## 设置

| 设置 | 用途 |
|---|---|
| `gushen.editorMode` | `platform`：原版界面（默认）；`basic`：旧版简化编辑器 |
| `gushen.platformAssetsPath` | 原版资源快照绝对目录，包含 `snapshot.json` 和 `guthon/`；空值使用内置资源 |
| `gushen.designerAssetsPath` | 仅 basic 模式使用的旧版资源包目录 |

资源升级时，完整准备新版快照及哈希清单，关闭页面，替换 `platform-assets` 或把 `platformAssetsPath` 指向新版目录，再重开页面。不要混用不同版本的主脚本、依赖和 worker。

适配器可识别同一构建结构下的压缩变量改名。若平台改变启动方式、组件接口或 JSON 保存结构，会明确报不兼容，需要升级适配器；不能保证任意版本只换资源即可兼容。保留旧资源目录便于回退。

## 保存与兼容范围

- 原版设计器加载后先记录归一化基线；字段对话框初始化的默认值与页面脚本视图的展示换行，不作为用户修改直接写回。
- 只将字段简单属性、前端事件的实际差异写回原文；支持在已有对象下增加简单属性与事件字符串。
- 不整页覆盖，保留原文件的其他格式、别名、未知属性、服务端内容和数值字面量。
- 文档版本不匹配时拒绝旧请求；JSON 损坏或重复键时停止编辑。
- 保存期间合并重复保存，字段编辑继续同步；VS Code 管理保存、撤销、重做和多视图文档。

**当前边界：**不支持布局、字段/按钮增删与重排、数据源或服务端事件修改。部分原版控件入口虽仍存在，超出范围的改动会被拒绝，不能据此判断已保存。模板、下拉定义、平台字典和校验规则的完整元数据尚未导出到本地，相关列表为空，已有引用保持原样；不伪造这些定义。复杂、自定义组件需继续逐页验证。

尚未复刻服务端 `changePageJSON` 的全部转换行为；当前通过归一化前后差分和受限原文修改支持上述范围，不用于完整页面结构设计。

## 验证

运行 `npm test` 和 `npm run check`，无需安装 npm 依赖。包含 JSON 精确修改、默认值保护、字段/事件新增、冲突、嵌套弹窗、保存并发及资源加载测试。默认使用仓库自带的匿名页面样本，不依赖业务工作区。可设置环境变量 `GUSHEN_SOURCE_ROOT` 指向谷神导出的源码根目录（含 systems/），对真实页面进行只读语料检查；已在 826 个真实页面上解析验证，并在其中 743 个页面上验证字段精确修改，不写回业务文件。

隔离浏览器已验证原版设计器启动、字段对话框无修改打开、字段改名、页面脚本只读查看、Monaco 编辑前端事件、内存 JSON 回写和保存回执；测试拦截外网且未观察到外网请求。真实 VS Code 界面的交互验证以交付记录为准，不将浏览器测试视为所有复杂页面兼容的证明。

## 独立项目开发

开发环境：Node.js 22 或更新版本、Python 3.9 或更新版本。资源下载额外使用 curl。不需要安装 npm 依赖。

```sh
npm test
npm run check
npm run package
```

安装包输出到 `dist/gushen-page-editor-0.2.0.vsix`。`dist/` 不纳入 Git。

使用真实导出源码验证（可选）：

```sh
GUSHEN_SOURCE_ROOT=/path/to/exported-source npm test
```

更新平台资源：`npm run assets:download`，会联网并更新 `platform-assets/` 及哈希清单；完成后重新测试和打包。下载前先保存旧资源用于回退。

源码调试：用 VS Code 单独打开本项目目录，按 F5。可在扩展开发窗口中打开 `test/fixtures/source/systems/SYS-OFFLINE/pages/P/G/PG-OFFLINE.json`，选择谷神页面编辑器。

项目仅包含插件实现、原版资源、匿名测试样本和维护工具；业务页面、浏览器配置和隔离安装目录不随项目复制。
